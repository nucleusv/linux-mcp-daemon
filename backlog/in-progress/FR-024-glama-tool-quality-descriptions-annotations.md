## Analysis

Written 2026-09-29 from the code (46 callable tools: 37 core in `HandleToolsList`, 8 in `dockerTools()`, `daemon/reload-config`). Every fact below cites the file; `tools.go` = `internal/rpc/tools.go`, `spawner.go` = `internal/worker/spawner.go`, tool files are under `internal/tools/`. Scores are only those in the table above; where a tool is not in it the scores are **not visible** (Glama's page was fetched twice again on 2026-09-29: it still shows only the same 20 rows, truncated after `logs/dmesg`; nothing for network/nslookup, arp, ping, processes/delete, services/list, journal-control..users/list or docker/*).

### A. Facts that apply to many tools (referenced as F1-F6)

- **F1 privileges.** Unprivileged calls run as the caller's mapped OS account and need no grant (kernel permissions apply). `privileged: true` needs `allowed: true` for that tool in the caller's grant, else the error is `Permission denied. Hint: You are not authorized to use 'privileged: true' for this tool in mcp-sudo.yaml` (spawner.go:76). Ten tools take a `path` and, run as root, also need `paths:` in the grant; a path outside it is refused with `user U is not authorized to run T on path P as root` (tools.go:816-824; `config.PathTools` = files/list, read, create, update, find, filetype, chmod, chown, disks/free, disks/usage). The path is cleaned before the check; unless the grant covers `/`, symlinks in any path component are refused (`_no_follow`, tools.go:835). An MCP user mapped to uid 0 is refused (spawner.go:51). Over `mcpd stdio` `privileged: true` is always refused (spawner.go:37). The 8 docker tools always run as root, take no `privileged` argument, and are refused without `allowed: true` (docker.go:185-188). `daemon/reload-config` is checked in the master against `allowed: true` (tools.go:770).
- **F2 output_format.** `json`, `yaml`, `table` and `wide` all return the SAME JSON text in almost every tool (e.g. files/list list.go:120, find.go:120, free.go:60, mounts.go:92, packages.go:75, users list.go:91). Exceptions: `disks/performance` (real YAML, performance.go:115), `processes/top` (`wide` = wider text layout, top.go:177), `logs/journal-control` (only `json`, one JSON object per line via `journalctl -o json`), `disks/partitions` (any non-empty value gives indented JSON, no `output_format` in its schema), docker/* (`Structured()` = same four words, allow.go:203). Tools that ignore `output_format`: logs/dmesg, logs/logins, kernel/system-control, files/read, files/filetype, network/trace-path, processes/delete, services/manage (always text); network/curl, ping, nslookup, arp (always JSON). The schema text "e.g. json, yaml, table, wide" therefore over-promises; say "json for structured output; text otherwise".
- **F3 timeout.** Every worker call is killed at the global worker timeout, 30 s (`configs/daemon.yaml:15`), or the tool's `tools: <name>: timeout_seconds` override (handler.go:79; shipped config overrides only `disks/usage` = 300, daemon.yaml:35). On expiry the answer is `timed out after N seconds - the call was stopped` (spawner.go). A tool's own longer timeout (curl `timeout`, docker/exec `timeout`) cannot exceed it.
- **F4 paths.** Path tools reject a relative path in the master: `path must be absolute, got "x"` (tools.go:800). Other tools (disks/health `device`, etc.) validate their own names.
- **F5 errors** come back as `isError: true` text, no structured error object; a tool-level failure (bad argument, missing file) is plain text such as `failed to open file: ...`.
- **F6 per-user text.** `tools/list` appends a "you are authorized to run as root" hint to 8 descriptions only for users whose grant allows it (tools.go:21-59), so a description a scanner sees may differ from what a granted user sees.

Justifications for the non-obvious ones: files/create - overwrites an existing file's content (create.go:53) so destructive, but writing the same content twice is a no-op, so idempotent. files/update - line replacement overwrites, append repeats on every call, so destructive and NOT idempotent. chmod/chown - overwrite the previous mode/owner; setting the same value again reports `unchanged` (chmod.go:64, chown.go:52), so idempotent. processes/delete - a signal cannot be undone and a second call fails with `no such process` (delete.go:57), not idempotent. services/manage - stop/restart/disable interrupt a service and restart/reload act every time. kernel/system-control - a write overwrites a live kernel setting (destructive), writing the same value again is a no-op (idempotent); it is `readOnly: false` because the same tool writes when `value` is set. network/curl - any HTTP method is passed through (curl.go:53), so it can POST/DELETE to remote systems: not read-only, destructive, not idempotent, open world. network/ping - opens and immediately closes a TCP connection (ping.go:81), no state change, but reaches outside the host. docker/manage - `remove` deletes a container; stop/restart/kill interrupt it; not idempotent (`unchanged` on 304 only for start/stop, manage.go:78). docker/exec - arbitrary code as root in a container. docker/prune - deletes objects the caller did not name; a repeat removes nothing more, so idempotent, but the effect is irreversible. daemon/reload-config - replaces in-memory config and closes sessions of removed/re-tokened users (tools.go:646) but deletes no host data: `destructive: false`, repeat with unchanged files changes nothing.

Titles are proposals (Glama's Conciseness/Purpose do not read them). docker/* are local-socket, so `openWorld: false` (task rule).

### D. Cross-cutting findings

**FALSE or misleading claims in current descriptions/schemas (fix before rewriting)**

1. **cpu/list** - schema `topology_only` "Only return basic core topology" has no effect: the field is parsed and never read (`cpu/list/list.go:12-14`, whole function). Description "Retrieves CPU topology" also overstates: output is raw /proc/cpuinfo, text shows only the first logical CPU, no sockets/cores/threads (list.go:74-101). Remove the parameter or implement it.
2. **docker/exec** - "30s default timeout (300s maximum)" and `timeout` "default 30, maximum 300" are unreachable: the worker is killed at the global 30 s (`configs/daemon.yaml:15`, `spawner.go` context timeout, `handler.go:79`) unless `tools: docker/exec: timeout_seconds` is set (shipped config sets only `disks/usage`, daemon.yaml:35). Also in `internal/tools/docker/exec/README.md:5,12` and `docs/website/docs/mcp-api/tools/docker/exec.md:5`. The same ceiling makes docker/prune's 120 s and docker/manage's/logs' 60 s client timeouts moot.
3. **files/list** - "Lists a directory like ls -la": dotfiles, `.` and `..` are only shown with `all: true` (`files/list/list.go:132-139`); the default is `ls -l`.
4. **files/create** - "Create a new file or replace file contents": with omitted/empty `content` it only touches and never truncates an existing file (`files/create/create.go:38-49`); it also silently creates parent directories (create.go:35) - undisclosed.
5. **processes/delete** - "Terminates a specific process": it sends any of 10 signals (SIGSTOP, SIGCONT, SIGHUP, SIGUSR1... included, `delete.go:19-23`), default SIGTERM, and returns on delivery without checking the process exited.
6. **auth/sudo-rules** - "Returns your authorized tools": only root grants; every tool is callable unprivileged without any grant (tools.go:639 comment; docker and daemon/reload-config are the exceptions). JSON keys are capitalised Go field names (config/sudo.go:24-45).
7. **memory/usage** - `detailed` "return raw /proc/meminfo instead of summary" only holds for text output; with `output_format: json` it is ignored (`memory/usage/usage.go:33,61`).
8. **disks/performance** - "equivalent to iostat ... I/O wait times": the values are cumulative kernel counters since boot, not per-interval rates and no `%iowait`/`await` (`disks/performance/performance.go:59-83`).
9. **files/read** - "chunking/streaming support": no streaming; reads into memory, default cap 10 KiB, binary refused (`files/read/read.go:26,53-66`).
10. **kernel/system-control** - "(read-only, or only certain keys) by mcp-sudo.yaml": there is no read-only mode; `sysctl.read_only` is rejected at load (`config/sudo.go:60-65`); only `write_keys` restricts, read-only = no `allowed` grant.
11. **output_format** schemas in ~25 tools say "json, yaml, table, wide" - all identical JSON (F2); logs/dmesg's `output_format` "Output format" and kernel/files/... accept-and-ignore.
12. **cpu/list, network/nslookup, others** - schema type vs code: `network/curl.timeout`, `network/ping.port` and `.timeout` are typed `number` but decoded into Go `int`, so `2.5` fails `invalid arguments` (`curl.go:20`, `ping.go:17-18`). `network/nslookup.record_type` omits AAAA which the code and README accept (`nslookup.go:47`).
13. **files/filetype** (and only it, tools.go:36) points to `files/stat`, which is NOT in `tools/list` (worker/resource only); an agent cannot call it. Point to `files/list` instead.

**Description vs README/docs disagreements**

- `files/read/README.md` says the tool is internal-only for the `file:///` resource; it is a public tool.
- READMEs for files/create, files/update, files/find, logs/dmesg (and several others) are generic boilerplate ("This package implements the X tool/resource ...") that say nothing true or specific; `network/ping/README.md` documents `timeout` "in seconds (defaults to 5)" while the schema has no description; `network/nslookup/README.md` intro lists AAAA, its schema block does not; `cpu/list/README.md` "Returns native CPU topology" repeats claim 1. Docs pages under `docs/website/docs/mcp-api/tools/*` copy the description verbatim (`files/read.md`, `files/create.md`, `cpu/list.md`, `processes/delete.md` verified), so a rewrite must change code, README and page together (`check_docs.sh`, `check_readmes.sh`).

**Inconsistent terminology**

- `tools_group` is `system` for `services/manage` and `services/list` (tools.go:386,401) but `services` in the tool name, and both share `linuxctl_verb: "services"`; `kernel/system-control` vs its `sysctl` verb; `logs/journal-control` vs `journal`; `network/trace-path` runs `traceroute`.
- "privileged: true" / "run as root" / "Run as root" / "Set to true to run as root" / "Run as root - required" are all used for the same parameter, with different completeness (only some say a grant is required).
- Result-size words: "capped", "truncated", "safe limit"; caps exist only in files/read (10 KiB default), dmesg (30 KiB), curl (1 MiB), docker/logs+exec (1 MiB); none in find, packages, journal (lines only), sysctl read_all, list.
- Case of JSON keys: `buffCache` next to `swap_total` (memory/usage); `1_min` keys (load-average); `maj:min` (disks/list).
- Empty result: `[]` (most), `null` (disks/mounts, network/arp), empty string (find, mounts text), or a sentence (`No services found...`, `Directory is empty.`).
- Descriptions with `(Hint: ...)` appended per user (F6) vs static text in the docs page.
