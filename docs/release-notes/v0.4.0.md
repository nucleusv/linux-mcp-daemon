## Upgrading from 0.3.5

Nothing has to change: existing configs, tools and their output are the same. The new Docker tools are off until you grant them in `mcp-sudo.yaml`; without a grant they are not even listed in `tools/list`.

- **New: Docker tools.** Read and manage containers on the host through the Docker Engine API over its unix socket - no `docker` CLI, no new dependency. Docker must already be installed and running; mcpd never installs it.
  - Read: `docker/containers`, `docker/images`, `docker/volumes`, `docker/networks`, `docker/logs`, plus one-object views `container://{name}/{view}`, `image://{name}/inspect`, `volume://{name}/inspect` and `docker-network://{name}/inspect`.
  - Act: `docker/manage` (start, stop, restart, kill, pause, unpause, remove), `docker/exec` (one command in a running container, exit code and stderr reported), `docker/prune` (reclaim one kind of unused object per call).
  - Safe by construction: every `docker/*` call runs as root (the Docker socket is root-owned) and is refused without an explicit grant. The tools that name a container take a `containers:` list of name or ID globs (each tool has its own, so `exec` can be narrower than `manage`); `prune` takes a `prune:` list of the *kinds* it may reclaim. A grant without its list refuses everything. See [mcp-sudo.yaml](https://nucleusv.github.io/linux-mcp-daemon/v0.4.0/configuration/mcp-sudo/).
- **`linuxctl get docker network bridge`** (and `container`, `volume`, `image`) now reads that one object, the way `describe` does. Before, `get docker <keyword> <name>` fell through to the group's default tool and answered with the wrong data.
- **A wrong word is an error, not a wrong answer.** `linuxctl get docker networkz` now stops with `no read target "networkz" in group "docker"` and exit code 1; it used to print the container list and exit 0.
- **Extra words are reported.** `describe` and template `get` reads print `Warning: N extra argument(s) ignored: ...` instead of dropping them silently, the same as tool calls already did.
- **`--` ends `linuxctl`'s flags.** `linuxctl exec docker web-1 -- echo hello` used to lose `echo` and run `hello`; everything after `--` now reaches the container as-is, so `-- ls --color` works.
- **Tab completion** for `get docker` now offers `containers` and the `container` / `network` / `volume` / `image` keywords.
