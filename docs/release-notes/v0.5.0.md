## Upgrading from 0.4.1

**One breaking change: the Docker resource templates were renamed.** If a user's `resources:` grant in `mcp-sudo.yaml` names `container://`, `image://` or `volume://`, rename the keys. There are no aliases: the old names are now `unknown resource`, and a read under a grant that still has them fails.

| 0.4.1 | 0.5.0 |
|---|---|
| `container://{name}/{view}` | `docker-container://{name}/{view}` |
| `image://{name}/inspect` | `docker-image://{name}/inspect` |
| `volume://{name}/inspect` | `docker-volume://{name}/inspect` |
| `docker-network://{name}/inspect` | unchanged (it already had the prefix) |

One command renames the grants, then restart or reload the daemon:

```bash
sed -i -E 's#^(\s+)(container|image|volume)://:#\1docker-\2://:#' /etc/mcpd/configs/mcp-sudo.yaml
systemctl restart mcpd        # or: linuxctl reload daemon
```

`linuxctl get docker container web-1 status` and the other keyword forms are unchanged; only the explicit `linuxctl resource <uri>` form and raw `resources/read` calls carry the new names. The `docker/inspect` grant under `tools:` is unchanged.

Everything else needs no changes.

- **New: `cron/manage` and `crontab://{user}/{view}` - read, list and replace crontabs.** `linuxctl get crontabs`, `update crontabs --content ...`, `edit crontabs` (opens `$EDITOR`, like `crontab -e`, and refuses the save if the crontab changed meanwhile). Your own crontab needs no grant. Another account's needs `privileged: true` and a rule naming it in your `cron/manage` grant (`users: {name: {view: true, edit: true}}`; no wildcards; `root` is view-only). The crontab is read and written with the `crontab` command, as the target account, so `cron.allow` and `cron.deny` still apply. **Writing a crontab schedules commands as that user, and the job outlives the session and the token; mcpd stores the text exactly as given and does not inspect it.** Read the [crontab risks](https://nucleusv.github.io/linux-mcp-daemon/v0.5.0/configuration/permissions-and-risks#crontabs) before you grant `edit`. See [`cron/manage`](https://nucleusv.github.io/linux-mcp-daemon/v0.5.0/mcp-api/tools/cron/manage).
- **New: `timers/list` - systemd timers**, with the unit each starts, its schedule, next and last run, and last result. Read-only; `services/list` never showed them. See [`timers/list`](https://nucleusv.github.io/linux-mcp-daemon/v0.5.0/mcp-api/tools/timers/list).
- **New: MCP annotations on every tool.** `tools/list` now carries `title`, `readOnlyHint`, `destructiveHint`, `idempotentHint` and `openWorldHint` for all 48 tools, so a client can decide what needs a confirmation.
- **Changed: all tool descriptions rewritten** for agents: what each tool is for, when to use a sibling instead, side effects and grants, parameter interactions, what comes back. Several descriptions that overstated what a tool does were corrected.
- **Image: the container now includes `cron`** (the `crontab` command), so `cron/manage` works in the Docker and Kubernetes deployments. Inside a container a call sees the container's own crontabs.
- **Fixed:** `timers/list` reported the next run of monotonic timers (`OnBootSec=`, `OnUnitActiveSec=`) as `never`; the crontab worker now resolves the target account in its own namespace, because a master in a container numbers accounts differently from the host.
- **Docs:** real READMEs for every resource template, the `docker/manage` page lists all seven actions, and the `linuxctl` command reference is in alphabetical order with `timers` and `crontabs` as their own sections.
